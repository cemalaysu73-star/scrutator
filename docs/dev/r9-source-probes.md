# R9 source probes (organisation-scoped sources)

Probed on 2026-11-08, before any module was written, with one or two requests per source and the user agent
`scrutator/1.0.0rc5 (+https://github.com/cemalaysu73-star/scrutator) source probe` (no personal address). Targets were
safe, well-known organisations only: OWASP (owasp.org), Insecure.Com / Nmap (nmap.org), ICANN, example.com, and for the
GLEIF relationship endpoints one large public company group (Alphabet / Google, organisation records only). A random
label (`zq` + 12 hex characters) stood in for "does not exist".

Checklist each source had to pass: **stable** (a versioned, documented endpoint), **documented**, **terms allow
automated use** (as read on the date above), **replayable** (a plain GET whose answer can be compared later) or clearly
marked non-replayable, and **deterministic** (exists / absent tell apart by HTTP status or JSON, not by page wording).

## What the probes changed in the design

- Wikidata's official-website match can land on a product (nmap.org → the Nmap software item). The organisation is
  taken only from items that are organisations; a product item is reported as "the domain is the official site of a
  product, not of an organisation" and nothing is derived from it.
- GLEIF exact-name lookups for OWASP find nothing (the foundation has no LEI). An empty answer is reported as "no LEI
  record under that exact name", never as "not a company".
- GitHub can answer 504 for a while; a 5xx is a source failure, never "the organisation has no GitHub account".
- The GitHub org object carries an e-mail address and the members endpoint carries people: only the fields listed in
  docs/organisation.md are stored, and the member endpoint is reduced to a count from its `Link` header.
- Package metadata (PyPI `author_email`, npm `maintainers`, RubyGems `authors`, crates `published_by`) names people:
  every registry record is a fixed projection that leaves those fields out.
